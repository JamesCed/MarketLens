# =====================================================================
# Decision Support System for SME Business Planning and Market Entry
# -- Python package requirements.
#
# This list has been audited against every `import`/`from ...import`
# statement in the codebase (app/, tests/, seed.py, app.py) -- including
# packages that are only imported INDIRECTLY at runtime, e.g. PyMySQL
# (loaded by SQLAlchemy from the "mysql+pymysql://" connection string in
# app/config.py, never `import pymysql` directly) and openpyxl (loaded
# by pandas.read_excel() in app/services/data_import_service.py, never
# `import openpyxl` directly). Everything the app actually needs to run
# is listed below -- nothing more, nothing missing.
#
# ---- Normal install (inside a virtual environment) ----
#
#   python -m venv venv
#   venv\Scripts\activate          (Windows)
#   source venv/bin/activate       (macOS/Linux)
#   pip install -r requirements.txt
#
# ---- Force prebuilt-wheel-only ("binary") install ----
# Use this if a normal `pip install` ever tries to compile a package
# from source (slow, and fails without a C/Fortran compiler installed --
# most common on a brand-new Windows machine or a very new Python
# version). It forces pip to use ONLY prebuilt wheels for every package
# in this file (and their dependencies) and fails fast instead of
# compiling if one isn't available -- every pin below has a prebuilt
# wheel for Python 3.10-3.13/3.14, so this should simply work.
#
#   Windows (PowerShell):
#     python -m pip install --upgrade pip
#     python -m pip install --only-binary=:all: -r requirements.txt
#
#   macOS / Linux:
#     python3 -m pip install --upgrade pip
#     python3 -m pip install --only-binary=:all: -r requirements.txt
#
# See README.md for the full setup walkthrough.
# =====================================================================

# PINNED BELOW 0.28 ON PURPOSE -- THIS IS WHAT STOPPED THE AI TEXT
# FROM EVER APPEARING.
#
# Neither line above depends on a specific httpx, so pip is free to
# take the newest one. That is fine until you look at what openai
# 1.51.2 does with it: _base_client.py builds its HTTP client with
#
#     SyncHttpxClientWrapper(..., proxies=proxies, ...)
#
# passing `proxies` UNCONDITIONALLY, even when the value is None.
# httpx deprecated that argument in 0.26 and REMOVED it in 0.28.0
# (28 November 2024), so on any fresh install -- which is every
# `pip install -r requirements.txt` on Render -- building the client
# raises
#
#     TypeError: Client.__init__() got an unexpected keyword
#                argument 'proxies'
#
# ...at the first attempt to write a recommendation. It is not a
# transient hiccup and no API key fixes it: the client cannot be
# constructed at all, so USE_LLM_RECOMMENDATIONS, the key and the
# model name are all beside the point and the page falls back to
# rule-based wording permanently. It stayed invisible because
# llm_service caught everything in a bare `except` -- see the note at
# the top of that file, now fixed.
#
# 0.27.x is the last line that still accepts `proxies`, so this holds
# httpx there. If you later move openai to a release that stopped
# passing it, drop this pin at the same time.
httpx>=0.27,<0.28

# --- Production WSGI server (deployment only) ---
# app.py uses Flask's built-in development server, which handles one
# request at a time and prints a warning telling you not to serve it
# publicly. On a host (see DEPLOYMENT.md and the Procfile) gunicorn
# serves wsgi.py instead.
#
# Deliberately a FLOOR (>=) rather than an exact pin, unlike everything
# above. This project runs on Python 3.14, which is newer than gunicorn
# 23.0.0, so pinning that exact release risks a build failure on a Python
# it predates; a floor lets pip take the newest compatible version.
# waitress is a pure-Python drop-in kept as a fallback -- if gunicorn
# ever misbehaves, change the start command to
#     waitress-serve --port=$PORT wsgi:app
gunicorn>=23.0.0
waitress==3.0.0

pytest==8.3.2

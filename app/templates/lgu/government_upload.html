How your file is handled:
  • All or nothing. If any row cannot be read, nothing is imported and your existing data is left exactly as it was. You will get the row number, the column and the value for each problem, so you can fix the file and upload again.
  • Blank is fine; wrong is not. An empty numeric cell is filled with that column's own average (data imputation). A cell with something unreadable in it — 12o instead of 120 — is reported and refused, because silently averaging a typo would hide it.
  • Barangay names must be official. A misspelling is rejected with a suggestion. Importing it as typed would create a row nothing in the system ever reads.
  • One row per business beats one row per barangay. Include psic_code and the system counts competitors per industry per barangay, which is what drives the saturation scores, the city-wide rankings and the trend reports. A barangay summary with only permit_count still imports, but it cannot tell a coffee shop from a hardware store.
  • Everything recalculates on success. The city-wide recommendations, the saturation map and the trend reports all pick up the new figures on the next page load — no re-seeding, no restart.
  • The uploaded file itself is not stored — only the parsed data rows are saved.

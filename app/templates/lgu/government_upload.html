Privacy notice for uploads

What is collected. Barangay zoning figures and business permit lists. From a permit list only the barangay, industry, line of business, status and permit number are read.

What is kept. Totals only — one row per barangay and permit counts per industry per barangay, with your account and the upload date. The file is deleted right after processing; no business name, permit number or file row is stored.

Purpose. Market saturation scores, city-wide recommendations, trend reports and the Diversification Plan — nothing else. Never sold or shared outside MarketLens.

Who can see it. LGU accounts (Encoders and Data Stewards) and system administrators. Business owners see only the resulting scores and counts per barangay, never your file.

How long. Uploaded data: {{ kept_upload_days }} days after upload. Audit trail (who uploaded what, when, from which device): {{ kept_audit_days }} days. Both are then deleted automatically. A staged upload not published within 60 days expires and is deleted.

Questions or requests. {% include "shared/_dpo_contact.html" %}. Full Privacy Policy

Before you upload, remove personal information. Delete columns with owner or proprietor names, contact numbers, e-mail addresses, home addresses, TIN or other ID numbers and birth dates. MarketLens does not need them, and a file that contains them is refused.

How your file is handled:
  • All or nothing. If any row cannot be read, nothing is imported and your existing data is left exactly as it was. You will get the row number, the column and the value for each problem, so you can fix the file and upload again.
  • Required columns must be filled; wrong is never accepted. An empty cell in a numeric column that is not required is filled with that column's own average (data imputation). A cell with something unreadable in it — 12o instead of 120 — is reported and refused.
  • Personal information is refused. A file with owner names, contact numbers, e-mail or home addresses, ID numbers or birth dates is not imported; remove those columns first.
  • The contents are checked, not only the file name. A renamed program, PDF or web page, a workbook with macros, and a password-protected or damaged workbook are refused.
  • Barangay names must be official. A misspelling is rejected with a suggestion. Importing it as typed would create a row nothing in the system ever reads.
  • Market Data drives the recommendations. Each permit in force is counted as one competitor for its industry in its barangay. Those counts drive the saturation scores, the city-wide rankings and the trend reports.
  • One record per barangay. Every upload saves one Gov't / Zoning row per barangay (a permit list is totalled per barangay), so the dataset records stay small and the pages stay fast.
  • A combined file works too. A permit list that also carries the zoning columns (like the sample dataset) fills both tables, whichever target you pick.
  • Staged first, live after approval. A file that passes these checks is saved to the staging area as a batch. An LGU Data Steward reviews it (and can reject it with a reason, shown under Your uploads); a System Admin then publishes it. Only then do city-wide recommendations, the saturation map and the trend reports use it — no re-seeding, no restart.
  • The uploaded file itself is not stored — only the parsed totals are saved, and a staged batch’s rows are cleared once it is published or rejected.
